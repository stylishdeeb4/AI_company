# 役割
AI業務改善診断ビジネスの毎日LP / HP改善運用の方針書です。

# 目的
SNS投稿案の毎日作成を主軸にする運用から、LP / HPを毎日改善して受け皿を強くする運用へ切り替えるためです。

# 使い方
日次のCodex自動化設定、LP改善の優先順位確認、作業方針の共通認識に使います。

# 保存先
`company/workspace/outputs/final_outputs/20260611_lp_daily_improvement_operation.md`

# 完了条件
毎日の改善対象、優先順位、保存先、品質基準が明確であること。

## 1. 方針転換
- これまでの主軸:
  - 毎日SNS投稿案を作る
- これからの主軸:
  - 毎日LP / HPを1つ改善する

理由:
- 既にSNS導線の初期設計はできている
- 受け皿であるLP / HPの比較検討導線を強くした方が、無料AI活用チェックへの遷移効率を上げやすい
- 日次の積み上げ対象として、HP内のコラム、FAQ、CTA、サービス説明の改善が資産になりやすい

## 2. 毎日の基本動作
毎回の実行では、以下の順で進める。

1. 現在の `index.html` `service.html` `faq.html` `columns.html` を確認する
2. 今日の改善対象を1つだけ選ぶ
3. 既存ページ改善を優先する
4. 必要ならコラムや補助ページを1つ追加する
5. リスク表現、専門判断、実績表現を確認する
6. 成果物と作業ログを保存する

## 3. 改善対象の優先順位
### 最優先
- CTA文言の改善
- ファーストビューの改善
- 無料AI活用チェックへの導線改善
- サービス比較の分かりやすさ改善

### 次点
- FAQの補強
- コラム一覧から各テーマへの導線改善
- 注意事項、リスク説明、安心材料の補強
- 相談前の不安解消コンテンツ追加

### その後
- 業種別コラム追加
- 運営者情報、問い合わせページ、法務ページの独立
- 実際の予約導線やフォーム接続前提のUI改善

## 4. 改善の判断ルール
- 1回の作業で複数の大きな論点を同時に触らない
- 迷ったら、新規追加より既存導線改善を優先する
- 迷ったら、見た目より導線を優先する
- 迷ったら、コラム追加よりCTA改善を優先する
- 迷ったら、ユーザーの比較検討を助ける内容を優先する

## 5. 毎日見直すべき論点
- トップページで誰向けサービスか一目で分かるか
- 無料AI活用チェックへの導線が十分に強いか
- サービスの違いが分かりやすいか
- FAQが申し込み前の不安を解消しているか
- コラムがSNS流入の受け皿になっているか
- 専門判断や機密情報の注意が分かりやすいか

## 6. 品質基準
- 誇大表現がない
- 専門判断をAIが代替するように見せない
- 実績がない内容を実績として書かない
- 仮想事例は仮想ケースと明記する
- CTAが明確
- どのページからも無料AI活用チェックに戻れる
- 日次改善の意図が説明できる

## 7. 成果物の保存ルール
- 日次改善メモ:
  - `company/workspace/outputs/agent_outputs/YYYYMMDD_lp_daily_improvement.md`
- 日次作業ログ:
  - `company/workspace/logs/work_logs/YYYYMMDD_lp_daily_improvement_log.md`
- 実装対象:
  - `company/workspace/outputs/final_outputs/lp_hp_project/ai_business_diagnosis_lp/`
